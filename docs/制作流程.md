# 制作流程与实现约定

## 内容路径

主题、题材、官网、参考照片和讲述重点 → Codex live web research + JSON Schema → 来源、确定程度、叙事与约8镜分镜 → GPT-Image-2逐镜生成 → Tingting逐句旁白 → 测量每句音频 → Remotion时间线 → 封面 → ffprobe媒体验收。

建筑围绕空间、结构与历史事件；博物馆挑选2至3件相关馆藏。研究必须带真实来源和证据摘要，来源不足时返回needsInput。fact、legend均必须引用来源；imagination可以无引用。来源、主张和镜头关联通过共享Schema校验。未知的祭礼、人物动作和布局不能当考古事实。

## 时间线

每镜时长是用户设置的最短时长与实际旁白总时长加句间/收尾空隙的较大值，向上取整到30fps。每句音频单独序列、字幕同步实际音频区间；不使用三星堆固定5秒槽位，也不自动拉快中文语速。实际总时长不在60至90秒时停止渲染，要求用户修正脚本或时长。

## 局部更新

- 旁白变更清除对应audioHash，保留旧音频；再次合成仅重新生成这段旁白。
- 提示词变更清除对应imageHash；再次合成仅重新生成对应画面。
- 镜头顺序、适配、焦点或时长变更仅影响合成。
- 标题变更使封面过期，单独重做封面或完整一键制作刷新；已有成片版本不覆盖。
- 官网、主题或重点变更使研究输入Hash变化，完整制作重新研究。
- 替换图片视为主动采用的素材；完整制作复用，不把上传素材自动改回生成图。

## 任务与恢复

queued → running → completed/failed/cancelled；启动时把残留queued/running标为interrupted，用户手动继续。每镜画面和音频完成即保存；取消停止后续阶段，已有素材保留。生成图像和封面在请求前写pending journal，已落盘结果可在继续完整制作时恢复；网络响应丢失但没有本地图片时无法确认服务端结果，因此不自动重试连接错误或超时。明确429/502/503/504最多重试两次。

版本保留：图片/旁白/封面输出采用独立文件名；生成前和每次保存记录项目快照。网页可查看历史图片、封面及已导出视频，完整音频版本可从快照追溯。不提供任意旧项目状态的一键回滚。

## 本地接口

GET /api/health；GET/POST /api/projects；GET/PUT /api/projects/:id；POST /api/projects/:id/upload；POST /api/projects/:id/jobs（full/research/image/audio/cover/render）；GET /api/jobs；POST /api/jobs/:id/cancel；GET /api/events（SSE）；GET /api/projects/:id/download。项目编辑需要当前revision，制作期间拒绝编辑。媒体仅通过/media提供图片、MP3与MP4，成品下载只能访问登记输出。

生成模板位于prompts/research.txt、research.schema.json、cover.txt；每镜完整图像提示词保存在项目数据和相邻prompt.txt。认证由本机CLI管理，浏览器不提供密钥输入。
